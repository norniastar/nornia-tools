# 性能冲刺报告：Nornia Tools

## 结论

7 个页面「打开到能用」p75 全部变快，几何平均 **2.34 倍**。首页、时间戳、UUID、URL、计算稿纸 5 页达到「降一半」的目标（降 57%～76%）；JSON 编辑器（降 35%）和文本代码对比（降 38%）没达到，原因见下文。视觉、功能、文本、统计脚本都没变：护栏 35 项全绿。

## 前后对比（配对测量）

口径：fast4g（RTT 20ms、下行 4Mbps）、CPU 不限速、冷缓存、1440×900；nginx 开 gzip 模拟线上 Cloudflare 压缩。
A = 基线 `ec8386e`，B = 优化后，两个版本同时起服务，A、B 交替各测 10 次。测量时段 2026-10-30 06:15～06:22。

| 页面 | 优化前 p75 (ms) | 优化后 p75 (ms) | 降幅 | 传输字节 |
|---|---|---|---|---|
| 首页 / | 2429 | 595 | 76% | 668 → 116 KB |
| JSON 编辑器 | 2137 | 1392 | 35% | 668 → 423 KB |
| 时间戳转换 | 1971 | 820 | 58% | 668 → 125 KB |
| UUID 生成器 | 2056 | 874 | 57% | 668 → 121 KB |

## 每一步的贡献

| 步骤 | 改了什么 | 主要收益 |
|---|---|---|
| 1 | 6 个工具组件 `React.lazy` 按需加载 | 主包 gzip 669 → 111 KB。首页 2044 → 511 ms，简单工具页约 2.0 s → 0.8 s，JSON 2508 → 1985，对比 6054 → 4679 |
| 2 | Monaco 从 jsDelivr 改为同源打包（只带 JSON/YAML/Go） | 对比页去掉跨域串行瀑布：4679 → 约 3600 ms；不再依赖 jsDelivr 的可用性 |
| 3 | JSON 过滤用的 Babel（206 KB gzip）改为用到时再加载，聚焦过滤框时预取 | JSON 页传输字节 638 → 433 KB，1985 → 约 1390 ms |

逐步明细和假设见 `perf/实验日志.md`。

## 没达标的两页卡在哪

- **JSON 编辑器（1393 ms）**：剩下的大头是 `jsoneditor` 完整包（gzip 288 KB），里面打包了 Ace、Ajv、取色器。可以换成 `jsoneditor-minimalist` 并自带精简版 Ace（只要 JSON 模式），估计还能再省 150 KB 左右、约 300 ms。风险是 Ace 版本和主题换了会有视觉差异，需要截图让你确认。
- **文本代码对比（3488 ms）**：Monaco 编辑器核心本身就有 gzip 约 1 MB（`edcore.main` 带全部编辑器功能）。进一步做法是只引入 Diff 需要的那部分 contrib，收益不确定，而且容易漏掉功能（查找、折叠、右键菜单等），需要逐项确认；另一个方向是先显示可输入的 textarea 外壳，Monaco 到了再接管，但交接时的丢字、对齐护栏工作量不小。
- 每次构建在这台 2 GB 内存的 VPS 上要 20～35 分钟，迭代成本很高。以上两项我先列为建议，要不要继续做由你决定。

## 用户能感知到的变化

- 切换到某个工具时，那个工具的代码第一次用到才下载（同一会话内后续切换走缓存）。在慢网下首次切换会有一个短暂的空白（`Suspense` 的 fallback 为空，没有加骨架屏），随后正常淡入。
- JSON 过滤：第一次在过滤框输入时，如果预取还没完成，结果会晚几百毫秒出来。
- 其他视觉、交互、动画全部不变（两种宽度的截图逐像素一致）。

## 回滚办法

- `git revert` 这几个 perf 提交后推 main，CI 会重新构建部署；
- 或者在 Actions 里手动运行 `Verify, Publish And Deploy`，`image_sha` 填 `ec8386e` 对应的完整 SHA，直接回到旧镜像，不需要重新构建。

## 风险

- Monaco 现在跟着站点自己发布，版本由 `package.json` 里的 `monaco-editor` 锁定，不再自动跟随 CDN。升级时需要重新跑护栏。
- 代码拆成多个块后，部署期间如果用户还开着旧页面，切换工具时可能请求到已被删除的旧块（新镜像里没有旧文件）。表现是切换失败，刷新即恢复。目前的 nginx 镜像每次部署都是全量替换，这个风险在部署那几秒到用户刷新之间存在。
- CI 构建时间会变长（Monaco ESM 模块多）；GitHub runner 内存充足，影响应小于这台 VPS 上看到的 20～35 分钟。
- 线上没有 CrUX 真实用户数据（流量不够），线上结论只能靠上线后的直接测量。
